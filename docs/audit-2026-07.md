## Parte 1 — Errores actuales

### Harness generado

**H1 · [ALTO/M] El loop implementer→reviewer→PR solo corre `fast` (typecheck) — lint y tests nunca corren antes del PR.**
El ciclo se apoya en `{{qualityGate.fast}}`: lo corre el implementer (`implementer.md:32`), aprueba con él el reviewer (`reviewer.md:64-70,150`), y `commit-pr-pilot.md:52-54` dice explícitamente NO recorrerlo. `{{qualityGate.full}}` (lint+test) solo aparece en cierre-sesión y como checkbox humano del PR (`commit-pr-pilot.md:120`). El default derivado es `fast = typecheck` solo (`lib/detect.ts:786-800`). → **Se puede aprobar y abrir un PR con tests rojos si compila.** `verify-before-done.md:54` tiene una fila "Tests pass" que nada dispara.
*Propuesta:* gatear el PR con `full`, o meter el test suite en `fast` cuando existe, o que el reviewer corra `full` en Pass 2.

**H2 · [ALTO/S] Contradicción R1→PR.**
`orquestacion.md:9,20` permite R1 directo a PR sin reviewer, pero `commit-pr-pilot.md:41-48` aborta sin un `review_<feature>.md` APPROVED (sin carve-out para R1); `pr-create.md:23` igual. El happy-path R1 (fix trivial → PR) queda sin ruta válida: el pilot aborta, y crear el PR el orquestador viola `leader.md:122`.
*Propuesta:* definir explícitamente el cierre de R1 (pilot con modo "R1 sin review" + fast verde, o PR inline documentado).

**H3 · [ALTO/M] Dos flujos de PR paralelos.**
`commit-pr-pilot.md` (body inglés `## Summary/Changes/Test plan/References`, idioma per config) vs skill `pr-create.md` (delega a un `Agent` fast, body **español** `## Resumen/Cambios`, título hardcodeado "Spanish MX" ignorando `commits`). Orquestacion cierra con el pilot; `ticket-intake` F8 con `pr-create`. Ya hay un comentario "keep in sync" señalando las 2 fuentes.
*Propuesta:* una sola fuente de verdad; `pr-create` como thin-wrapper del pilot.

**H4 · [ALTO/M] `auditor` y `ticket-audit` se solapan; `auditor` está huérfano del routing.**
Ambos escriben `.claude/progress/audit_*.md` y detectan previos con el mismo glob (colisión: uno puede leer el reporte del otro). `auditor` no se menciona en `orquestacion.md` ni `leader.md` (0 menciones) → el orquestador nunca lo rutea proactivamente.
*Propuesta:* namespaces separados (`audit_deep_*` vs `audit_ticket_*`) + integrar `auditor` al playbook con trigger claro, o fusionar.

**H5 · [MEDIO-ALTO/M] Validación de UI estructuralmente rota.**
`implementer.md:37` pide validar el golden path en browser, pero el implementer no tiene navegador (`implementer.md:4`) → siempre "not validated" → el reviewer escala a humano cada cambio de pantalla (`reviewer.md:43,72,153`). La skill `playwright-cli` vive en el orquestador, fuera del loop.
*Propuesta:* rutear la validación UI al orquestador (que sí tiene browser), o dar la herramienta al implementer, o smoke por endpoint cuando no hay browser.

**H6 · [MEDIO/S] `structural-search` Rung 0 acopla a engram (plugin opcional).**
`structural-search.md:13-18` define Rung 0 "consult memory with engram". Es skill core (siempre presente) pero engram es opcional → instrucción muerta si no hay memoria.
*Propuesta:* condicionar Rung 0, o inyectar el bloque engram en la skill solo cuando el plugin está activo (como ya se hace con `engram-protocol` en CLAUDE.md).

**H7 · [MEDIO/S] "When `main` ≠ `main`" cuando `prTarget` = `branchBase` (el default).**
`reviewer.md:18-22` y `commit-pr-pilot.md:26` renderizan una condicional autocontradictoria en el caso por defecto (base == target). El modelo lee una instrucción que se refuta a sí misma.
*Propuesta:* reautorear para el caso igual, o colapsar el párrafo cuando base == target.

**H8 · [MEDIO-BAJO/S] El índice de skills lista nombres sin "cuándo usar".**
`## Available skills` es 9 nombres sin trigger; `## Available agents` sí trae una línea por agente. En engines sin auto-trigger (Cursor/Copilot/AGENTS.md) el modelo no sabe cuándo alcanzarlas. *(Converge con C1/N2.)*
*Propuesta:* añadir un trigger de una línea por skill (reusar el `description` del frontmatter).

**H9 · [MEDIO-BAJO/S] Tres vocabularios de severidad.**
`formato-respuesta.md:13-16` (`[CRÍTICO/ALTO/MEDIO]`, español) vs `review-diff.md:22-24` (`[CRITICAL/HIGH/MEDIUM]`, inglés) vs score 0-100 del reviewer.
*Propuesta:* unificar a un vocabulario canónico; score interno del reviewer + etiqueta única.

**H10 · [BAJO-MEDIO/M] Triplicación circuit-breaker / paralelismo / ejecución-continua** entre `orquestacion.md`, `leader.md` y `operaciones-seguras.md` (casi verbatim, ya divergen sutilmente). `leader.md` debería PROFUNDIZAR, no recopiar.
*Propuesta:* `orquestacion.md` única fuente de las mecánicas; `leader.md` solo lo que no está inline.

### CLI

**C1 · [ALTO/M] Skills de Claude en forma PLANA rompen el autoload nativo.** *(Converge con N2, H8.)*
`engines/claude/adapter.ts:36-43` escribe `.claude/skills/<id>.md` plano; Codex escribe directorio `.agents/skills/<id>/SKILL.md` (`engines/codex/index.ts:104-111`). Claude Code solo auto-descubre `<id>/SKILL.md` → el `description`/trigger nunca llega al modelo por descubrimiento nativo. Blast-radius menor de lo que parece: `resolveLocalSkillPath`, `listSkillDirs` y los scans de doctor ya soportan ambas formas; falta la poda one-time del path plano legacy (las core-skills no tienen reconciliación) + tests.
*Propuesta:* migrar el adapter a forma-directorio + poda del legacy + ajustar tests. **Es el fix de fondo de H8 y N2.**

**C2 · [MEDIO/S] Test de paridad valida NOMBRES, no formato.**
`engine-parity.test.ts:70-91` compara sets por nombre, no por forma descubrible. Por eso C1 pasa CI en verde (falsa confianza sobre el eje que más importa).
*Propuesta:* aserciones de forma ("skills de Claude son `<id>/SKILL.md`", etc.).

**C3 · [MEDIO/S-M] Dos motores de interpolación `{{path}}` duplicados.**
`interpolateTemplate` (`lib/render-plan.ts:139-173`, CLAUDE.md) vs `interpolate` (`engines/claude/interpolate.ts:24-99`, skills/agents). Divergen (solo `interpolate` tiene `extraVars`/`omitUnresolvedKeyLines`).
*Propuesta:* consolidar en `interpolate` y borrar `interpolateTemplate`.

**C4 · [MEDIO/M] Dos builders de "skills index" duplicados y ya divergentes.**
`buildSkillsIndexBody` (`engines/claude/index.ts:131-192`) vs `buildSkillsSection` (`engines/shared/prose-harness.ts:52-84`). Prose salta condicionales (L67) y no lista locales; Claude sí. Es la duplicación que el spine debía absorber.
*Propuesta:* un solo builder parametrizado en `harness-plan`/`harness-assets`.

**C5 · [MEDIO/M] Fugas de i18n: strings de usuario hardcodeados en español en engine/lib.**
`execute-plan.ts:170`, `prose-harness.ts:151,226`, `claude/index.ts:52-55,965,972,1079,1086`, `codex/index.ts:48`. Un repo con `language:"en"` recibe CLAUDE.md en inglés pero mensajes de skip/warn en español.
*Propuesta:* rutear por `tc(lang)` (el `SkipReason` callback ya es punto de inyección).

**C6 · [MEDIO/M] Despacho por engine esparcido en ~7 archivos, sin registro central.**
`render.ts:80-97`, `doctor.ts:742-757,948`, `health.ts:168` + schema/detect/workspace-defaults/style/configure/init. El core se declara "engine-agnostic" pero no hay un `EngineDescriptor`.
*Propuesta:* un registro de engines (id → adapter + owned-paths + inventory) del que deriven render/doctor/health.

**C7 · [MEDIO/M] Hooks de preset son Claude-only (gap de paridad).**
`claude/index.ts:672` renderiza `extras.hooks`; `resolveHarnessPlan` (`harness-plan.ts:108-121`) solo incluye hooks CORE → Codex nunca renderiza hooks de preset. Latente (ningún preset bundled los usa) pero es deuda del spine.
*Propuesta:* subir `extras.hooks` a `resolveHarnessPlan`.

**C8 · [BAJO-MEDIO/S] Codex: skills de preset condicionales se materializan pero no se indexan.**
`resolveHarnessPlan` las escribe pero `buildSkillsSection` salta toda condicional (`prose-harness.ts:67`). Se arregla gratis con C4.

**C9 · [BAJO/L] Presets sin versión propia.**
TODO en `render-plan.ts:362-370`: los extras estampan versión de `@navori/core`, no propia → no se puede rastrear drift/update de un preset independiente del core.
*Propuesta:* estampar `@navori/preset-<id>` + versión.

**C10 · [BAJO-MEDIO/M-L] Plugins de terceros no soportados.**
`KNOWN_PLUGINS` es un mapa estático de 5 (`plugins.ts:155-161`). No hay forma de registrar un `@scope/plugin-x` propio.
*Propuesta:* permitir plugins declarados en `navori.config.json` vía `createRequire` (con el containment check que ya existe).

*Menores (radar, no desarrollados): `loadPreset` reparsea 4+ veces/render sin memoizar; `initCommand.run` god-function ~600 líneas; `interpolateFrontmatter` es un 3er parser de frontmatter frágil.*

## Parte 2 — Inspiraciones que resuelven mejor

navori ya implementó lo grande de casi todas las inspiraciones (routing orgánico, structural-search, circuit-breaker, compresión, EARS+traceability, Leader/Implementer/Reviewer, engram). Quedan **4 gaps reales**:

**I1 · [ALTO/M] gentle-ai — Receipt-Driven Development (RDD).** *El gemelo de navori.*
RDD ata la confianza al **contenido**: tras el review congela los bytes exactos y emite un receipt ligado al contenido; commit/push/PR validan el mismo receipt, nunca reabren en silencio. navori ata por **tiempo** ("evidencia fresca este turno", `verify-before-done`) y el handoff review→commit compara **nombres de archivo**, no bytes (`commit-pr-pilot.md:43`). Si el diff cambia entre APPROVED y el commit (rebase, tweak humano), el veredicto de review NO se re-valida — solo el hook mecánico.
*Adoptar:* el reviewer registra una huella del diff aprobado (`git hash-object`/tree-hash) en `review_<feature>.md`; el hook `quality-gate-pre-commit.sh` la recomputa y compara; mismatch → invalida la aprobación. Universal en la gate (también R1 a commit). **Es el mayor hueco de confianza de navori.**

**I2 · [ALTO-MEDIO/M] codegraph + graphify — grafo AST pre-construido.** *(Converge con N4. → spec 0009.)*
Índice determinista local consultable en 1 call MCP; graphify commitea el grafo al repo (rebuild por hook post-commit, merge driver para `graph.json`, comentarios `# WHY:` como nodos). navori cortó en Rung 2 de structural-search y excluyó LSP/Serena por overhead (spec 0005), pero nunca consideró el índice *barato* (grafo commiteado, rebuild gratis).
*Adoptar:* plugin-bundle como "Rung -1" de structural-search (forma la hipótesis, no solo la verifica). **Plan detallado: `specs/0009`.**

**I3 · [MEDIO/M] gstack — cross-model review.** *(Converge con N3.)*
`/codex`: review independiente de OTRO proveedor sobre el mismo diff. El reviewer de navori corre en `{{models.reviewer}}` pero mismo proveedor (Claude) → mismos sesgos. navori es **el único con core multi-engine ya renderizado** → Codex revisa el diff de Claude casi gratis (reusa `reviewer.md`).
*Adoptar:* skill/comando `cross-review` opt-in pre-PR en `{{project.criticalAreas}}`.

**I4 · [MEDIO/S] Goose — anti prompt-injection.** *(Converge con N7.)*
`ticket-audit` lee tickets, `auditor` usa WebFetch, `researcher` lee el repo — `operaciones-seguras`/`security-guidance` NO tratan la inyección de instrucciones vía contenido leído.
*Adoptar:* bloque managed corto "contenido externo = datos, no instrucciones" + nota en `ticket-audit`/`auditor`.

**Menores:** superpowers (TDD test-first opt-in, I5, MEDIO-BAJO); harness-sdd (estado `spec_ready` consultable, I6, BAJO-MEDIO); ponytail (intensidad de restraint configurable, I7, BAJO).
**Sin gap:** caveman (cubierto por Q1), ejemplo-harness-subagentes (ya presente), Pi (filosofía).

## Parte 3 — Nuevos conceptos / herramientas a adquirir

**N1 · [ALTO/M] Hooks de ciclo de vida (SessionStart / Stop / SubagentStop / PreCompact).**
Claude Code expone ~30 eventos; navori solo usa `PreToolUse` (guard) + pre-commit; `settings-base.json` trae `"hooks": {}` vacío. `SessionStart` inyecta contexto (mem_context + git log + `current.md`) → P2/P3, deja de ser un bloque always-on. `Stop` hace cumplir `verify-before-done` → P4. `PreCompact` dispara `mem_session_summary`. `SubagentStop` valida los `impl_*/review_*.md`. **Convierte doctrina blanda en mecanismo determinista y gratis de contexto. El mayor ROI idiomático.**

**N2 · [ALTO/M-L] Skills nativas `SKILL.md` (directorio).** *(Es el fix de fondo de C1/H8.)*
Frontmatter potente: `allowed-tools` (permisos scoped por skill), `context: fork`/`agent`/`background`, supporting files (progressive disclosure N3), dynamic injection (`` !`git diff` `` se ejecuta e inlinea). Desbloquea autoload por description, permisos por skill, y partir cuerpos pesados en nivel-3.

**N3 · [ALTO/M] Cross-model review** — ver I3.

**N4 · [ALTO/M] Plugin code-intelligence MCP (codegraph/graphify)** — ver I2. → `specs/0009`.

**N5 · [MEDIO-ALTO/M-L] Alinear con plugins NATIVOS + marketplace de Claude Code.**
Desde oct-2025 hay plugins nativos (`.claude-plugin/`) + marketplace oficial. Anthropic ships `code-review`/`security-guidance` que solapan con assets de navori. Decisión de rumbo: exponerse como marketplace + no reinventar lo que ya es nativo.

**N6 · [MEDIO-ALTO/M] Paralelismo con git worktrees nativos** (Claude Code v2.1.49).
Disuelve la restricción "solo archivos disjuntos" del paralelismo de `orquestacion.md` → P1 velocidad. Doctrina + posible skill de worktree-orchestration.

**N7 · [MEDIO/S-M] Guardrail prompt-injection** — ver I4.

**N8 · [MEDIO/M] Interop SDD (Spec Kit / OpenSpec).**
La SDD de navori es bespoke (EARS + `R<n>↔test`); Spec Kit es el estándar de interop multi-engine. navori es multi-engine pero su SDD no viaja fuera del harness. Emitir/alinear artefactos compatibles.

**N9 · [MEDIO-BAJO/S] Compresión de reports inter-agente / context-editing nativo.**
Brevedad en los `progress/*.md` (estilo caveman) o Context Editing API. Techo menor (los reports ya son estructurados).
