## Operations on data and infrastructure

Read-only by default. Before mutating data, schema, or infrastructure (DB, storage, deploys, cloud resources), read and propose; don't mutate without the user's explicit opt-in for THIS task.

- **DB / queries**: read-only by default (`SELECT`, `EXPLAIN`, flags like `onlyRead`). `INSERT/UPDATE/DELETE/DROP/ALTER/TRUNCATE` require the user to ask for it explicitly.
- **Shell commands**: inspecting is free (`ls`, `cat`, `git status/diff/log`). Destructive ones (`rm -rf`, `git reset --hard`, force-push, `chmod -R`) are routed by the harness to `ask`/`deny` and a hook blocks them — don't try to bypass that layer.
- **Code search**: use the native tools `Glob` (files by name/pattern) and `Grep` (content). They're read-only, faster (ripgrep underneath), and already skip `node_modules`/`.git`, so they don't ask for permission. Reserve shell `find`/`grep` for what the tools don't cover — search by FS metadata (`-size`, `-mtime`, permissions) — and use it only when critically necessary. `find` is not pre-approved on purpose: with `-exec`/`-delete` it's not purely read-only, so asking for permission there is the right safety net, not a nuisance.
- **If a destructive mutation is legitimate and necessary**: explain what it does and why, and let the user confirm or run it. Never disguise it with variables, subshells, or `--no-verify` to skip the gate.
- **Command blocked by permission/policy → STOP (circuit-breaker)**: if a tool call lands on `deny` or the user rejects the permission prompt, the block is the answer — **0 retries**: don't re-issue the same command or ask for the same permission again in a loop. If instead the command only requested a non-pre-approved permission (pending prompt, not a `deny` nor a rejection), you're entitled to **1 (one) legitimate alternative approach** — e.g. using the native `Grep`/`Glob` tool instead of shell `grep`/`find` — and if that one doesn't pass either, you stop. The alternative changes the path, never the same command again. If the operation is intentional and necessary, tell the user so they run it outside the agent; cycling on the block only burns tokens.
- **Sensitive data**: don't dump secrets, PII, or full dumps to logs, chat, or repo files.
