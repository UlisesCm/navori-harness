# Dependencies up to date — Design

Signal: migration of shared contracts (the citty command tree, the managed `citty` skill and the Pi runtime admission table), a critical area (managed-block and managed-file content, and the self-hosted render mirror), and a hard ceiling (`check:size`). Inputs: `requirements.md` (R1–R7), the scout research in `.navori/state/handoffs/scout_deps-update.md`, and the challenge in `.navori/state/handoffs/solution_review_0061-dependencias-al-dia.md`. This design does not repeat the scout's per-package tables.

User decisions (2026-10-26, binding):

1. Pi `verifiedFrom` is raised to `1.4.0`.
2. citty 0.2's help and error formatting is accepted. The CLI surface golden is re-baselined, and a clean-environment test covers the literal text that hooks match.
3. If the bundle exceeds 1650 KiB after M7, the work stops and the user decides. The plan contains no limit raise.

## Approach

All upgrades land in one PR to `dev`. The PR is split into nine milestones, and each milestone gets its own commit and its own evidence. The order is set by two constraints that the scout's "split citty and astro" advice did not account for:

1. **The bundle is already at its ceiling.** `bun run --filter navori build` followed by `check-bundle-size.mjs` on this branch's base (`89edd93e`) measured **1649.3 KiB against `LIMIT_KB = 1650`**, which leaves 0.7 KiB of headroom (measured 2026-10-26). A step that adds bundled bytes before another step removes some fails R7 on its own commit. citty 0.2.2 drops `consola`, which is its only consumer in the lockfile (confirmed by the challenge), so citty is the step that creates headroom.
   - All bundled runtime dependencies (citty, clack, zod, smol-toml, tsdown) come after the non-bundled steps, and citty is the first of them.
   - M5 must remain the first bundled commit even after a rebase onto `dev`.
2. **Each milestone must be checkable on its own.**
   - Non-bundled tooling goes first because it cannot change `dist/`.
   - Pi comes after the bundled steps because the render it triggers depends on M5's `dist/`.
   - The website goes last because nothing else depends on it and its parity proof needs a stable build.

Discarded alternatives:
- *Several PRs, as the scout suggested.* The user decided against this; it is binding.
- *One commit for everything.* A failure could not be traced to a single upgrade, and the bundle-size order above could not be shown to hold.
- *Pinning held versions* (citty 0.1, astro 5). This contradicts R3.

For every breaking API, the repo adopts the library's own new mechanism instead of building a compatibility layer. The mechanisms are citty's `default` subcommand, clack's `spinner().error()`, and Astro's `compressHTML` option. A compatibility shim would be a second copy of library behavior, and the `migrations` mirror already showed that such copies go stale on upgrade.

## Decisions

### D1: citty 0.1.6 → 0.2.2 (R3, R4)

- **Remove the hand-written dispatch mirror in `migrations.ts`.** Citty 0.2.2's `runCommand` supports `default: "<sub>"`, which runs that subcommand when no subcommand is named. It throws `E_DEFAULT_CONFLICT` if a command also defines `run`, and it still calls the parent `run` after an explicit dispatch, the same as 0.1.6. So `migrationsCommand` drops `run` and `ranSubCommand` and declares `default: "list"`. The parent keeps `args.json` so `migrations --help` still lists it.
  - The existing e2e cases in `cli.e2e.test.ts` keep their current results. The challenge confirmed this against 0.2.2's `findSubCommandIndex` and `_isValueFlag`:
    - `migrations` runs `list`.
    - `migrations --json` and `migrations --json --limit=1` run `list` with the same argv.
    - `migrations list …` and `migrations restore …` dispatch explicitly.
    - `migrations --limit 5` still fails with `Unknown command 5`, as documented today.
  - `migrations -- list` now reaches the default `list` once.
  - Rejected: rewriting `ranSubCommand` to copy `findSubCommandIndex`. That is the same mirror again, and the next bump breaks it again.
- **The parser engine changed, not only subcommand resolution.** 0.1.6 used its own mri-style parser; 0.2.2 uses `node:util.parseArgs` with `strict: false`. The verified differences, each now pinned by `citty-parse.test.ts`:
  1. **Declared string flag.** `--cwd x` and `--cwd=x` both yield `"x"`, unchanged. A bare `--cwd` with no value yields `""`.
  2. **Undeclared flag with a space-separated value.** 0.1.6 consumed the next token (`--foo bar` → `foo="bar"`). 0.2.2 yields `foo=true` and leaves `bar` as a positional.
  3. **Undeclared numeric values.** These stay strings (`--limit=1` → `"1"`), where 0.1.6 produced the number `1`. The only reader, `migrations` → `runMigrationsList` → `intFlagOrExit`, applies `String(raw)`, so the visible result is unchanged. The existing e2e case `'migrations --limit=N' truncates` proves it.
  4. **Repeated declared string flag.** The last value wins (`--ack a --ack b` → `"b"`). 0.1.6 built an array that the `.split(",")` callers (`tools.ts`, `plan.ts`, `master.ts`) never typed. This replaces a latent crash with defined behavior and is accepted.
  5. **`--no-<x>` tokens.** They are stripped before parsing, anywhere before `--`. A declared boolean that defaults to `true` (`init --no-render`) still negates. No repo arg is named `no-*`.

  Subcommand resolution also changed: a declared string or enum flag on a parent now consumes its value before citty looks for the subcommand name. `command-tree.test.ts` (Testing strategy) guards the related #466 class of bug.
- **Fix the ~216 `type: "string"` args at their use sites.** 0.2 types optional string args as `string | undefined`. This is a type-only change: the runtime value was already `undefined`. Each use site gets the fallback it already relied on (`?? process.cwd()`, `?? default`) or an explicit guard. Adding `as string` or `!` to silence the checker is not allowed, because it would hide a real missing-value path.
- **Help and error format (user decision 2).**
  - What changes:
    - `navori -v` alone now prints the version.
    - Help shows value hints (`--cwd=<cwd>`).
    - Errors lose consola's ` ERROR ` badge.
    - Non-`CLIError` errors print once.
    - The unknown command's name is colored with cyan ANSI codes unless `NO_COLOR=1`, `TERM=dumb`, `TEST` or `CI` is set. `isTTY` is not consulted.
  - The golden is re-captured with `node packages/cli/scripts/capture-cli-surface.mjs`. The re-baseline counts as parity only if:
    - the set of cases, their `args`, and their exit `status` are identical;
    - every `--flag` name in the old golden appears in the new one.
  - `parseSubcommands` (`^USAGE navori (\S+)$`) must still parse the root help.
- **Hooks that match CLI output (challenge C1).** Two managed hooks decide "this is an old CLI" by matching text in the output:
  - `quality-gate-pre-commit.sh` matches `*"Unknown command gate"*`.
  - `session-start-context.sh` matches `*"Unknown command"*`.

  A 0.2-based CLI always knows `gate` and `tools session-context`, so the old-CLI branch is unreachable from it, and the coloring cannot misclassify these probes. `cli-surface.test.ts` gains the case `keeps the literal text hooks match under a clean environment`. It spawns `dist/index.js` with only `PATH`, `HOME` and `TERM=xterm` set, so `NO_COLOR`, `CI` and `TEST` are absent, and asserts:
  - `no-such-command` exits 1 and its output contains `Unknown command`;
  - `gate --help` and `tools session-context --help` exit 0.

  The hooks themselves do not change. The `tools-session-context.test.ts` and `quality-gate-foreign.test.ts` fixtures keep the old ` ERROR ` shape because they simulate old CLIs.
- **The managed `citty` skill is updated. This touches a critical area (managed-block content).**
  - `lib-skills/citty.md` is rewritten for 0.2:
    - The description and hard rule 3 drop "citty 0.1".
    - The `enum` type (with `options`) is added.
    - The false gotcha "Only the run command's hooks fire" is replaced. Parent `setup`/`cleanup` run around the child in both versions.
    - New rule: a parent `run` also fires after a subcommand, so use `default` instead.
    - New one-line note for repos still on 0.1: no `enum`, no `default`, and a mri-style parser. Detection is by presence of the dependency (`library-skills.ts`, entry `citty`), and `minMajor` cannot tell 0.1 from 0.2.
  - **Word budget.** The current managed body is about 504 words against `maxWords: 550`, measured the way `skill-caps.test.ts` does: `countWords` of `parseAsset(raw).managedBody`, user-section excluded. The rewrite stays under 550 by:
    - replacing hard rule 3 with the enum rule instead of adding one;
    - dropping the "Quick table" rows that repeat the example ("Named flag", "Required arg", "Lazy subcommand");
    - merging the two kebab/alias gotchas.

    The binding check is `skill-caps.test.ts` ("declares a valid type and respects its word cap").
  - `skill-security-quality.test.ts` changes its citty assertion. It now expects the 0.2 enum rule instead of `Citty 0.1 supports only…` and no longer forbids `type: "enum"`.
  - The marker *mechanism* is not changed: no change to marker syntax, hash or version stamping, `fmkeys`, the user-section, or the anti-rollback guard. Only the managed block's *content* changes:
    - `hash` changes and `version` is stamped.
    - User repos receive the new body through the normal `updated` path on their next `render`/`sync` after a release.
    - This repo's mirrors are refreshed with `bun run render:apply`.
- **The `clack` skill does not change.** Its claims ("a prompt returns `value | symbol`", `isCancel` narrows) still hold in 1.8.1, where `CANCEL_SYMBOL` is a `unique symbol`.

### D2: @clack/prompts 0.10.1 → 1.8.1 (R3, R4, R7)

- **API changes adopted:**
  - `spin.stop(msg, 1)` becomes `spin.error(msg)` in `add.ts`. 1.x's `SpinnerResult.stop(msg?)` has no exit-code argument; `error()` is its failure state.
  - `validate` callbacks in `init.ts` receive `string | undefined` and normalize with `val ?? ""` before testing.
  - `p.isCancel` keeps narrowing. Any remaining errors are fixed at the site the typechecker flags, with no casts.
  - `note()` no longer dims lines (1.6.0). This is accepted as a library-owned visual change.
- **Bundle size:** both versions were measured in isolation with a minified probe that imports the namespace the repo uses (`bun build --minify`, in the session scratchpad):

  | Package | Old | New | Change |
  |---|---|---|---|
  | clack | 42.3 KB | 24.6 KB | −17.7 KB |
  | citty | 83.2 KB | 9.1 KB | −74.1 KB, from dropping consola |
  | zod | 391.0 KB | 391.9 KB | +0.9 KB |

  The scout's "growth" figure for clack was the package's raw, unminified `dist` file, not bundle output, so the two numbers do not conflict. Neither probe is the tsdown/rolldown pipeline, so the binding evidence is `check:size` after M5, M6 and M7. **UNVERIFIED** until those run. Above 1650 KiB the work stops for the user (user decision 3).
- **Runtime floor:** clack 1.8.1 and `@clack/core` declare `node >= 20.12.0`, and citty 0.2.2 needs only `node:util.parseArgs`. Both are below the CLI floor of `>=22.12`, so R2 holds.

### D4: astro 5.18.2 → 7.4.2 (R3, R4)

- **Old output defaults are pinned explicitly where Astro 7 changed them:**
  - `compressHTML: true` is set in `astro.config.mjs`, with a one-line comment. Astro 7's default `'jsx'` strips whitespace between inline elements; source: [upgrade guide v7](https://docs.astro.build/en/guides/upgrade-to/v7/), read 2026-10-26.
- **The other Astro 7 changes are no-ops for this site, and no config is added for them:**
  - Advanced routing: the reserved `src/fetch.ts` does not exist.
  - Sätteri as the default Markdown processor: no page goes through Astro's Markdown pipeline.
  - Removed `astro:transitions` internals: not used.
- **Astro 6 changes that can still show up:**
  - Tags render in source order.
  - Endpoints whose URL has an extension are reachable only without a trailing slash. Build output is unaffected.
  - The Rust compiler rejects unclosed tags and invalid nesting. A markup fix is allowed only when the comparator's visible text stays identical.

  Source: [upgrade guide v6](https://docs.astro.build/en/guides/upgrade-to/v6/), read 2026-10-26, partially read: the fetcher truncated it. The build plus the comparator are binding.
- **Mechanical parity (challenge C4).** `apps/website/scripts/compare-dist.ts <before> <after>` exits 0 only when every gated check passes, and prints a report otherwise.
  1. **Hash normalization**, applied to file paths and file contents: `_astro/<name>.<8-char hash>.<ext>` becomes `_astro/<name>.HASH.<ext>`.
  2. **File list:** the set of normalized relative paths, including `_astro/`, is identical.
  3. **Non-HTML outputs:** `*.md`, `*.txt`, `*.xml` and `robots.txt` are byte-identical after normalization.
  4. **Per HTML page:**
     - Visible text is identical. It is computed by removing comments and `<script>`/`<style>` elements, stripping all tags, and collapsing whitespace to single spaces. A `compressHTML` regression shows up here as missing spaces.
     - The sorted multiset of `href`, `src`, `srcset`, `id`, `for`, `lang`, `hreflang`, `rel`, `name`, `content`, `property`, `type`, `data-*` and `aria-*` attribute values is identical.
     - The sorted set of `<link>` and `<meta>` elements, with attributes sorted and `meta[name=generator]` excluded, is identical.
     - Inline `<script>` bodies are reported, not gated.
  5. **`_astro` CSS/JS:** per-file and total sizes are reported, not gated.

  Behavior that the comparator does not gate (client scripts in `BaseLayout.astro`, `Header.astro`, `InstallTabs.astro`, `LegacyRedirect.astro`) is covered by a browser smoke recorded in the PR body: language switch, install tabs, copy button, `/en/` and `/versiones` legacy redirects, and a visual check of `/`, `/es/`, `/zh-cn/`.
- **Two configurations.** Builds run with the defaults and with the deploy configuration (`SITE_URL=https://ulisescm.github.io SITE_BASE=/navori-harness/`), and `check-i18n.ts` passes in both.

## Failure modes

- **`check:size` above 1650 KiB at any bundled milestone (M5–M7), including after a rebase:** stop and ask the user (user decision 3). Do not shrink code and do not raise the limit.
- **citty parse behavior outside the D1 list:** `citty-parse.test.ts` or the existing e2e cases (`numeric flag validation (#283)`, the migrations dispatch cases) fail, and that blocks M5.
- **The mirror re-render goes stale after a rebase onto `dev`** (CONTRIBUTING step 2): re-run `bun run render:apply` after every rebase, before `check:render`. This applies to both the citty skill and `.pi/extensions/navori.ts`.
- **The Astro comparator fails:** fix the config or the markup. The comparator is never loosened.

## Migration

- **Users of the published CLI** need to do nothing: the engines are unchanged and the bundle is self-contained.
- **Repos with a Pi engine** receive the new `.pi/extensions/navori.ts` on their next `render`/`sync`. From then on, Pi 1.1–1.3 users get `navori_subagent` refusals until they upgrade Pi to 1.4.0 (user decision 1).
- **Repos that use citty** receive the rewritten skill block. Its text tells 0.1 users what differs.

## Testing strategy

Every milestone ends with `bun install --frozen-lockfile` and its acceptance commands (`tasks.md`). M9 ends with the full `bun check` (`qualityGate.full`) and the PR's CI.

Each new test answers a risk named above:

- `command-tree.test.ts` walks `main`, resolving lazy subcommands, and asserts that no command defines both `run` and `subCommands` and that every `default` names one of the command's own subcommands. This is the #466 class from D1, and it is why `ranSubCommand` can be deleted.
- `citty-parse.test.ts` pins the five parser behaviors in D1 through `runCommand` on a fixture command.
- `cli-surface.test.ts`, the new clean-environment case: the hook literals (C1).
